================================================================================
SNN-TORCS 展示软件 · 设计稿 (manifest)
================================================================================
0. 定位
--------------------------------------------------------------------------------
把「68 维状态 → SNN(T=4)→ 7 维 Q → 转向」全链路可视化,以两个验收指标
(决策速度 +10%、解码精度 ≥90%)为核心,面向评审现场演示。

--------------------------------------------------------------------------------
1. 运行环境
--------------------------------------------------------------------------------
- Linux(可考虑用 docker 封装 TORCS + conda env torcs_RL + 展示软件)
- 两档交付(目前仅考虑简易版):
  * 简易版:浏览器展示(后端 Python 推理 + TORCS)— 快速汇报、可远程看
  * 完整版:可执行程序(打包,双击即跑)— 离线交付、稳定演示 [暂缓]

--------------------------------------------------------------------------------
2. 布局:三栏固定(类似 VSCode 布局)
--------------------------------------------------------------------------------
+--------------+----------------+--------------+
|   主界面      |   实时状态面板  |    证据面板   |
|  (画面区)   |  指标 / Q 值    |  模型 / 命令 |
+--------------+----------------+--------------+
        模式切换 → 改变三栏各自内容,栏位不变

- 主界面     : 实时→TORCS 运行画面 / 回放→赛道俯瞰+轨迹 / 证据→材料详情 / 数据包→文件+录屏
- 实时状态   : 核心指标卡 + 7 维 Q 柱状图(高亮 argmax)
- 证据       : 模型卡 + 完整复现命令 + 指标溯源

--------------------------------------------------------------------------------
3. 核心数据流(贯穿展示的四要素)
--------------------------------------------------------------------------------
68 维状态 → SNN 网络 → T=4 时间窗 rate decode → 7 维 Q → 转向动作

  输入   : 68 维 float32 = focus(5)+speed(3)+opponents(36)+rpm(1)+track(19)+wheelSpinVel(4)
  网络   : FCANN: 68→256→256→7(ReLU)
           FCSNN: SnnLinear→LIF→SnnLinear→LIF→rate→Linear(同拓扑,可权重迁移)
  时间窗 : ours T=4 / baseline T=8;LIF thresh=0.5 decay=0.25;rate decode = spike_sum/T
  输出   : 7 维 Q,argmax → 转向 [-1,-0.5,-0.25,0,0.25,0.5,1.0];油门固定 accel=0.15

--------------------------------------------------------------------------------
4. 验收指标(双 gate,软件核心)
--------------------------------------------------------------------------------
  ① 决策速度
     定义  : ours forward 时延 ≤ 0.9×baseline     目标: +10%
     实测  : 41.6%(0.618ms vs 1.058ms)
     数据源: benchmark_policy_latency.py → latency_benchmark.json

  ② 解码精度
     定义  : 方案二 闭环完赛率(≥90% 即达标语义)  目标: ≥90%
     实测  : xxx(待填)
     数据源: eval_policy.py → ours_exp012_driving_15ep.json

  注意（暂时不管，先做一个视图）: 指标①是 ours(T=4)对 baseline(T=8)的对比。示例模型 exp013 实为
        baseline T=8,单放它演示不了速度优势;速度对比演示待最终 ours 模型
        (续训中)到位。

--------------------------------------------------------------------------------
5. 交付边界:展示软件推理运行包(关键)
--------------------------------------------------------------------------------
决策: 推理在软件侧 → 软件需一个“推理运行包”,但不含训练/诊断代码。
      给软件的最小集:

  [模型类]   snn_torcs/models.py、snn_torcs/snn_core.py
             → FCANN/FCSNN/LIF/SnnLinear,承接 .pth
  [环境对接] snn_torcs/env_wrapper.py、snn_torcs/run_mode.py、gym_torcs.py、snakeoil3_gym.py
             → 68 维观测 + 动作映射 + info 字段 + Xvfb/XML 启动管理 + UDP 连 TORCS
  [权重 IO]  trainer.py 的 load_state_dict / load_checkpoint_metadata(建议抽成 io.py)
             → 加载 .pth、读模型卡元数据
  [工具]     snn_torcs/utils.py(get_device / set_seed)
             → 设备/种子
  [配置]     configs/default.yaml
             → T / thresh / decay / output_dim / steer_values
  [运行时]   conda env torcs_RL(torch / yaml / numpy)+ TORCS(下游已自备)
  [资产]     示例模型 exp013 best.pth + 示例逐帧 JSON
             → 占位示例

  接口稳定性: 无论最终模型为何,68 维输入 / 7 维 Q / 动作映射 / per-step info
             字段都不变(网络拓扑与 env 固定)。故基于 exp013 开发,后续换模型零成本。

--------------------------------------------------------------------------------
6. 两种模式(栏内切换)+ 证据 / 回放数据包
--------------------------------------------------------------------------------
【模式 1 · 实时模式】
  - 输入    : 现场加载 .pth(示例 exp013,baseline T=8,接口稳定;最终模型续训中)
  - 推理    : 在软件进程内(自加载 .pth + 驱动 TORCS + 自测 forward 耗时)
  - 主界面  : 实时推理 + 调用 TORCS GUI 展示运行画面
  - 状态栏字段(逐步刷新):
        时间 · reward · step · 7 维 Q(柱状)· 动作(idx/steer)· speedX · trackPos
        · 推理耗时(forward ms,软件自测)· 路程(distRaced)
  - 数据来源: env_wrapper.py 的 info 已含 speedX/trackPos/angle/distRaced/reward/action;
              Q / 动作来自 model(state).argmax

【模式 2 · 回放模式】
  - 输入    : 加载 step-level JSON(逐帧日志,示例由 exp013 预生成)
  - 主界面  : 赛道俯瞰(加载 TORCS 固定赛道几何)+ 用逐帧 trackPos / distRaced / angle
              重建并回放赛车轨迹
  - 前置(必须): 当前 eval JSON 仅 episode 级聚合,需新增「逐帧记录 eval」产出 step-level JSON

【证据(支撑)】
  - 模型卡: checkpoint sha256 / stage / best_reward / episode
  - 完整复现命令行 + 配置(configs/default.yaml)+ 指标溯源(指标 ↔ 报告 JSON)

【回放数据包】
  - 给无法现场跑的环境离线播放: step-level JSON + 录屏 + README,打包成数据包

附录 A · 交付清单(打包给下游软件的内容)
================================================================================
前提: 下游已在 Linux 上自行装好 TORCS 仿真环境。故交付包【不含 TORCS 本体】。

建议目录结构:
  snn_torcs_handoff/
  ├── README.txt                 本文件(设计稿 + 交付说明)
  ├── run.sh                     启动脚本:启 TORCS + 加载模型 + 跑一轮推理示例
  ├── environment.yml            conda 依赖(torch/yaml/numpy,由 torcs_RL 导出)
  ├── model/
  │   └── exp013_best.pth        示例模型
  ├── code/
  │   ├── snn_torcs/             models.py, snn_core.py, env_wrapper.py, utils.py, io.py
  │   ├── gym_torcs.py
  │   ├── snakeoil3_gym.py
  │   └── configs/default.yaml
  ├── data/
  │   └── replay_example.json    示例逐帧 JSON(step-level,回放用)
  └── reports/
      ├── latency_benchmark.json 验收指标① 证据
      └── eval_exp013.json       验收指标② 证据 / 模型卡

要点:
  - 只给“推理运行包”,不给训练 / 诊断代码(见 §5)。
  - TORCS 由下游自备(已装)。
  - run.sh 是交接验收凭据:下游跑通 = 交接成功。

================================================================================
附录 B · 交接流程
================================================================================
[上游 · 交接前准备]
  1. 抽离 io.py(从 trainer.py 取 load_state_dict / load_checkpoint_metadata)
  2. 新增“逐帧 eval 记录”,用 exp013 跑出 data/replay_example.json
  3. 写 run.sh:启动 TORCS → 加载 exp013_best.pth → 闭环跑若干步 → 打印 per-step 数据
  4. 导出 conda env: conda env export -n torcs_RL --no-builds > environment.yml
  5. 按附录 A 打包: tar czf snn_torcs_handoff.tgz snn_torcs_handoff/

[传输]
  将 snn_torcs_handoff.tgz 交下游。

[下游 · 接收后验证]
  1. 解包
  2. 建 conda env: conda env create -f environment.yml
  3. 跑 run.sh,确认: TORCS 启动 + 模型加载 + 车跑起来 + 终端打印 per-step 数据
  4. 跑通即视为接口验收通过,开始开发展示软件

[风险提醒]
  - TORCS 版本一致性: 下游自装的 TORCS 需与本仓库 vtorcs-RL-color 兼容
    (UDP 协议 / 接口);若版本不同,env_wrapper / snakeoil3_gym 可能需调整。
  - 显示: TORCS GUI 需 X11;简易版(浏览器)若在后端跑,需虚拟显示或 X 转发。
